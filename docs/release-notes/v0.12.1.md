# v0.12.1 - Windows private storage permissions

> 2026-06-02 - Windows ACL hardening for state and artifact storage, with no
> breaking CLI, dashboard, or configuration changes.

## 中文

### Highlights

| 维度 | 改动 | 为什么重要 |
|---|---|---|
| **Windows storage** | 状态库与报告 artifact 在 Windows 上使用 DACL 私有化，只允许当前用户、SYSTEM 与 Administrators 访问。 | Windows 的 POSIX mode bits 不可靠；现在不会因为合成的 group/other bits 误拒绝启动，同时会真正替换宽 ACL。 |
| **State DB** | SQLite DB 和 WAL/SHM sidecar 会在读写模式下被 harden；只读 dashboard 打开不会修改权限。 | 运行态生成的持久化数据保持私有，dashboard 的只读路径也不会产生写入副作用。 |
| **Artifact files** | 覆盖已有报告和元数据文件时会重新 harden ACL，已有 artifact 目录在 Windows 上也会被收紧。 | 旧文件或外部工具留下的宽权限不会在后续写入后继续残留。 |

### Compatibility

| Surface | Before | After | Action |
|---|---|---|---|
| Windows permissions | 启动检查依赖 POSIX mode bits，可能误判 Windows 文件权限，也不能可靠替换显式宽 ACL。 | Windows 使用 PowerShell/.NET 替换 DACL；POSIX 继续严格检查 `0600` / `0700`。 | Windows 部署需要可用的 PowerShell 或 `pwsh`；正常升级即可。 |
| Read-only dashboard | 只读 state 打开需要避免触碰 SQLite 文件权限。 | `StateStore(read_only=True)` 严格只读，不创建、不初始化 schema、不 harden ACL。 | 无需配置变更。 |
| Demo output | Windows 跨盘 artifact 路径可能让 `relpath` 抛错。 | 跨盘时回退显示绝对路径。 | 无需操作。 |

### Verification

- `uv run pytest tests\store\test_permissions.py tests\store\test_artifacts.py tests\store\test_state.py tests\test_demo.py -q`
- `uv run ruff check src tests`
- `uv run pytest -q`
- 手工验证 Windows ACL 替换：先添加 `Users:(RX)`，调用 hardening helper 后只剩 SYSTEM、Administrators 与当前用户。

### Notes

- 已有父目录不会被任意改 ACL；只有本次新建的 DB 目录会被设为私有，避免误改项目根目录或共享目录。

## English

### Highlights

| Area | Change | Why it matters |
|---|---|---|
| **Windows storage** | State DB and report artifacts now use private Windows DACLs that allow only the current user, SYSTEM, and Administrators. | POSIX mode bits are not reliable on Windows; startup no longer rejects synthetic group/other bits, and broad ACLs are actually replaced. |
| **State DB** | SQLite DB files and WAL/SHM sidecars are hardened in read-write mode; read-only dashboard opens do not mutate permissions. | Runtime persistence remains private while the dashboard viewer stays side-effect free on the read path. |
| **Artifact files** | Existing report and metadata files are re-hardened on overwrite, and existing artifact directories are tightened on Windows. | Broad permissions left by older runs or external tools do not persist after later writes. |

### Compatibility

| Surface | Before | After | Action |
|---|---|---|---|
| Windows permissions | Startup checks relied on POSIX mode bits, which could misread Windows permissions and could not reliably replace explicit broad ACLs. | Windows uses PowerShell/.NET to replace DACLs; POSIX keeps strict `0600` / `0700` checks. | Windows deployments need PowerShell or `pwsh` available; upgrade normally. |
| Read-only dashboard | Read-only state access needed to avoid touching SQLite file permissions. | `StateStore(read_only=True)` is strictly read-only: no creation, schema init, or ACL hardening. | No configuration change required. |
| Demo output | Cross-drive artifact paths on Windows could make `relpath` raise. | Cross-drive paths fall back to absolute display paths. | No action required. |

### Verification

- `uv run pytest tests\store\test_permissions.py tests\store\test_artifacts.py tests\store\test_state.py tests\test_demo.py -q`
- `uv run ruff check src tests`
- `uv run pytest -q`
- Manually verified Windows ACL replacement: after adding `Users:(RX)`, the hardening helper left only SYSTEM, Administrators, and the current user.

### Notes

- Existing parent directories are not arbitrarily re-ACL'd; only a DB directory created by this run is made private, avoiding accidental changes to a project root or shared directory.
