# v0.13.0 - Dashboard LAN access + responsive UI polish

> 2026-06-03 - New `dashboard-lan` profile for intranet access, responsive
> breakpoints for tablets/small screens, and a unified button token system.

## 中文

### Highlights

| 维度 | 改动 | 为什么重要 |
|---|---|---|
| **LAN 访问** | 新增 `dashboard-lan` compose profile，宿主侧绑 `0.0.0.0:8787`，支持局域网/内网浏览。 | 默认 `dashboard` profile 仅绑 `127.0.0.1`，无法从其他设备访问；LAN profile 是显式 opt-in，安全硬门全部保留。 |
| **响应式布局** | 新增 1024px / 480px 两档断点（原仅 760px），修复 `.row` grid-area 冲突 bug。 | 平板（800–1024）与窄桌面下表单溢出、按钮错位问题消除；小屏触控目标 ≥44px。 |
| **按钮统一** | 新建 `.btn` + 4 modifier（primary / danger / ghost / default）CSS token 系统；全部模板迁移到新 token。 | 之前 `.action-link` / `.row-action` / `button.action` 三套样式各自演化、且与链接蓝撞色；现在 4 档视觉一致。 |

### Compatibility

| Surface | Before | After | Action |
|---|---|---|---|
| `dashboard` profile | `--allow-public` 启用时 Host allowlist 校验 + `csrf_secure=True`。 | `--allow-public` 跳过 Host 校验、`csrf_secure=False`。但 Docker 端口映射 `127.0.0.1:8787` 仅本地可达，无实际安全影响。 | 无需配置变更。 |
| `_STATIC_VERSION` | `20260601-admin-ui-v2` | `20260602-ui-polish` | 用户下次访问自动加载新 CSS（缓存失效），无需手动清缓存。 |
| Button CSS classes | `.action-link` / `.row-action` / `button.action` / `button.action.primary` | `.btn` + `.btn--primary` / `.btn--danger` / `.btn--ghost` | 无 API 改动；无配置文件格式改动；无新 CLI flag；无新 i18n key。 |

### Verification

- `uv run ruff check src tests tools`
- `uv run pytest -q`
- 手动浏览：Chrome DevTools 切 iPad（820×1180）和 iPhone SE（375×667），检查 `/`、`/settings`、`/login` 无溢出、按钮可点。
- LAN 验证：`docker compose --profile dashboard-lan up -d dashboard-lan`，同网段 `curl http://<host>:8787/healthz` 返回 200。

### Notes

- `--allow-public` 是显式 opt-in 信号；LAN profile 在可信内网段运行，接受明文 HTTP 风险。
- 公网部署仍需反代 + HTTPS + auth + rate limit（README 双语已更新）。
- `<a>` vs `<button>` 语义边界 100% 保留（`<a>` 用于 GET confirm entry，`<button>` 用于 POST mutating）。

## English

### Highlights

| Area | Change | Why it matters |
|---|---|---|
| **LAN access** | New `dashboard-lan` compose profile binds `0.0.0.0:8787` on the host for intranet browsing. | The default `dashboard` profile only binds `127.0.0.1`, unreachable from other devices; the LAN profile is explicit opt-in with all security gates preserved. |
| **Responsive layout** | Added 1024px / 480px breakpoints (previously only 760px), fixed `.row` grid-area conflict bug. | Form overflow and button misalignment on tablets (800–1024) and narrow desktops eliminated; touch targets ≥44px on small screens. |
| **Unified buttons** | New `.btn` + 4 modifier (primary / danger / ghost / default) CSS token system; all templates migrated. | Previously `.action-link` / `.row-action` / `button.action` evolved independently and clashed with link blue; now 4 consistent visual tiers. |

### Compatibility

| Surface | Before | After | Action |
|---|---|---|---|
| `dashboard` profile | `--allow-public` enforced Host allowlist + `csrf_secure=True`. | `--allow-public` skips Host validation, `csrf_secure=False`. Docker port mapping `127.0.0.1:8787` is localhost-only, so no real security impact. | No configuration change required. |
| `_STATIC_VERSION` | `20260601-admin-ui-v2` | `20260602-ui-polish` | Users get the new CSS automatically on next visit (cache bust); no manual clear needed. |
| Button CSS classes | `.action-link` / `.row-action` / `button.action` / `button.action.primary` | `.btn` + `.btn--primary` / `.btn--danger` / `.btn--ghost` | No API changes; no config format changes; no new CLI flags; no new i18n keys. |

### Verification

- `uv run ruff check src tests tools`
- `uv run pytest -q`
- Manual browser check: Chrome DevTools device mode iPad (820×1180) and iPhone SE (375×667) — verify `/`, `/settings`, `/login` have no overflow and buttons are tappable.
- LAN verification: `docker compose --profile dashboard-lan up -d dashboard-lan`, then `curl http://<host>:8787/healthz` from another machine on the same network returns 200.

### Notes

- `--allow-public` is an explicit opt-in signal; the LAN profile runs on a trusted network segment and accepts plaintext HTTP risk.
- Public internet deployments still require a reverse proxy + HTTPS + auth + rate limiting (README updated in both languages).
- The `<a>` vs `<button>` semantic boundary is 100% preserved (`<a>` for GET confirm entry, `<button>` for POST mutating).
